## Generic SDK follow-up

The current collector-domain layer rejects a `resourceMap` input when it is
used as another input's progressive dependency (`V1 supports finite target and
choice dependencies only`). Mosaic Workshop therefore bounds both exchange
maps independently and validates their equal totals and disjoint resource
types together at command acceptance. Reordering finite craft fields before
the two exchange maps keeps exhaustive exploration under the public CLI's
5,000-evaluation cap. All emitted commands are legal, but a future generic SDK
capability could make the receive-map UI domain react immediately to the
chosen give map without game-local validation or shared-SDK changes here.
